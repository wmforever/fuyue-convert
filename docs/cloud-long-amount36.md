# 长金额编辑：实测换行与有限空白预留

本批从 `7a3ceb25835b0fa2e032f4fe3cf158487aaafa90` 继续同一分支/草稿 PR。新增六份独立 300 DPI 扫描页：中英文各三份，覆盖长正数、长负数/前导零及金额右侧的 `TAIL 2097`。冻结旧值、新值、相邻文字、源图、字体与位置，然后实际 HTTP PNG→PDF→扫描 Word→未编辑/编辑 Office PDF→TXT。**这是 Word 编辑空间改进，不是原生 OCR 准确率提升。**

英文基线实际 Office PDF 和真实 HTTP 把 `123456789012.65` 拆成 `1234567890`、`12.65`，把 `-987654321098.80` 拆成 `-9876543210`、`98.80`；两份相邻文字控制甚至拆成三段。去掉空白后可能仍有全部字符，但数字字面量边界已被破坏，不能据此认定金额完整。

首版中文生成器把仅含 CJK fallback 字形的字体用于拉丁数字，源图自身缺字，三份中文编辑未执行。**保留首版 24 请求及缺字源证据，不计为中文编辑验收。** 修正为 CJK/Latin 分别绘制，独立冻结三份中文页，补跑 15 请求，没有重跑英文。两个实际生成器版本已恢复，并分别与冻结清单中的 generator SHA256 精确匹配。公开生成器现在默认使用正确字体；`--legacy-missing-latin` 仅复现被拒绝的首版缺陷。

## 最小有限实现与保护

已有浅色扫描页末数字词预留最多 15mm 右侧空白；但输出时再次受两倍字号宽度限制，长数字仍换行。现在先保留原空白检查，再仅对额外条带逐像素检查，把可用透明文本框预留最多扩至 **25mm / 8 倍词框高度**，同时限制在扫描图和原页面之内。移除重复的较小输出上限，让透明框使用已经证明安全的预留边界。

扩展仍只用于 scan-only、可靠浅纸色、数字末词、置信度至少 0.85、无旋转/倾斜、最多 512 OCR 词。已有 **250000 像素总预算不变**。未知字迹、已知邻词、暗纸、边界或预算不足不采用扩展；已通过的短预留空间保留。逐词遮罩形状/面积/z-index、原图、源词框和左上位置不改变。没有扩大遮罩擦除相邻文字，也没有改变识别参数、模型、低置信度回退、数字去重、PDF 可见性和超时门槛。

新增回归实际证明：扩展条带内一个未建模红点与已知邻词都拒绝长预留，仍保留原短预留；源图字节、遮罩及文本左位置相同，框不越过已检查的 25mm 边界。**27 项遮罩/采样/词框专项执行通过**，再进行一次完整干净构建。

四个行末金额的数字边界从 **0/4 → 4/4**，包括负号与前导零；未抹去或恢复成旧值。两份有相邻文字的金额不能安全预留，保持失败条件。六份未编辑 Office 页面 **300 DPI 渲染像素全部精确相同**；六份 Word 扫描图及遮罩全部精确相同，源文字、位置、字号等属性不变，只有符合条件的透明文本框宽度改变。原生图像不裁切，编辑后的 Word 只改指定文字，其他 ZIP 部件逐字节相同。

实际重开生成的 Office PDF 全页和金额裁剪均保存。另对前后各六份**实际渲染裁剪**调用固定 bundled 引擎，合计 **12 次单独的有限 ROI OCR**，只用作可见像素复核，不代替 HTTP 结果。四个最终行末值均完整精确，两个相邻控制仍读出分段。四个已改善编辑的实际像素差异全部落在透明金额文本框内，框外源内容逐像素不变。源码没有改动源 OCR 识别实现；本批没有额外抓取完整 OCR model，未冒称已逐对象比较全部识别置信度。

最终六页 HTTP 依赖图 **30 请求：27 成功、3 严格失败**。只有两份英文编辑全文/金额验收成功；中文三份不能算端到端验收，相邻英文即使接口成功也不能算金额正确。**不放宽 `OCR_VISIBILITY_UNCERTAIN`，不把成功状态、置信度或无空白 CER 当作完整性。** 中文原有“保留/相邻文字”的原生读序换行亦未处理：两份行末中文全文原始 CER 从约 2.8% 降至约 1.4%，剩余是该未改变的换行；英文两份原始 CER 降至 0。逐份原始全文、可见读数、数字边界、API 错误及框外像素检查见 [结果 JSON](cloud-long-amount36-results.json)。
