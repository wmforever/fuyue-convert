# 数值字面量保护：括号、单位、货币与分隔符号

本批从 `16af17f93a968b65ccd3196b80705c1e7420232f` 继续同一草稿 PR。实际生产 Java 去重把 `(048.65)` / `048.65`、`10%` / `10`、`10‰` / `10`、货币符号和分隔空格的负号误当作相同数字。冻结九份合成 OFD，各含四行原生文字、同位置扫描文字，以及扫描独有的 `NOVEL FOOTER 2094`。新增页脚让基线请求成功，避免只靠 `OCR_NO_NEW_TEXT` 揭示问题。**基线 9 个请求全部成功，却有 7 组数值差异被静默丢弃。**

修复只扩展 `OcrTextDeduplicator` 的比较字面量：保留紧邻数字、可隔空白的会计括号、Unicode 货币符号、百分比/千分比/万分比和正负号。空白自身不拼接数字；`12 34` 仍区别于 `1234`。原有数字、前导零、日期、小数、分组分隔符及位置重叠要求不变。相同符号旁的空格可容忍，`No.` 普通格式差异仍可去重。比较结果不修改原文、原生块、OCR 词框或原图。

冲突提示复用原有同字母上下文判断，并覆盖原文本相似比较会误判重复的字面量差异。例如本次实际引擎把 `10‰` 识别为 `10%o`，修复保留这一**错误的实际识别值**和原生 `10`，返回 `OCR_RECOGNITION_CONFLICT`；没有改写成 `10‰` 或选择某层为真值。修复不是通用金额语义解析器。
