## Small end-to-end smoke and unresolved failures

[Generator](../qa-samples/generate_cloud_smoke25.py), [bounded runner](../qa-samples/run_cloud_smoke25.py), [verifier](../qa-samples/verify_cloud_smoke25.py) and [frozen plan](cloud-consolidation25-plan.json) use two original synthetic inputs: bilingual digital TXT and clear English300-DPI scan, with record00842, amount127.50 and date2036-04-19. Manifest `35636dc45d0412d67a97d40b9ee36db3fac2138b7b11551ab704a68960e6d106`. Twenty dependency-ordered requests cover TXT/Word/PDF/OFD, native text, OCR, source scans and edits127.50→128.75.

The first run stopped after request9 failed. Its8 successful outputs and failed response are immutable. The runner was extended to resume from hash-verified successful artifacts and record failures without skipping independent remaining checks; the remaining11 requests then ran once. Both runner versions/hashes are retained. No completed conversion was repeated. There are20 distinct direct JVM Worker identities, all absent after teardown, ECHILD confirmed, no new zombies;17 historical audit/git zombies remain unchanged and unsignalled. Existing480/120/30/15-second suite/contract/request/teardown bounds stay active.

The digital Word/PDF extraction and edit controls have CER0 and exact numeric lexemes. Clean PNG→TXT, scan PDF→Word, scan Word→Office, and scan PDF→OFD→TXT/Word also preserve measured text and numbers. Two edited DOCX files change exactly one intended visible text node; every other XML property and all media remain unchanged. The original PNG is retained in its PDF, PDF OCR Word preserves the exact PDFBox300-DPI background pixels, and scan-OFD Word preserves the exact input OFD raster pixels. These checks do not make all subsequent compositions safe.

1. **Sparse digital fidelity OFD cannot re-extract TXT/Word here.** TXT→DOCX→Office PDF→OFD succeeds, but both OFD→TXT and OFD→DOCX return `OCR_NO_NEW_TEXT`. The native text is complete for this fixture yet occupies too little of the page for `ScannedContentDetector`'s conservative coverage gate. OCR of the full-page fidelity raster duplicates the native layer, so `OfdOcrSupport` refuses to call it complete. Simply trusting producer metadata or accepting a duplicate high-confidence OCR result could hide unknown text in a genuinely incomplete mixed page. The protection remains unchanged.
2. **Edited scan PDF→TXT reintroduces hidden original content.** The edited DOCX text nodes and Office PDF native text have amount128.75 and CER0. Direct visual inspection, however, shows overlapping original/overlay text in both the unedited and edited Office PDFs; the edited amount is not visually clean. Native-text correctness must not be described as visual correctness. With OCR enabled, API extraction reads the retained underlying raster again and produces both `127.50` and `128.75`, plus a duplicated title/year. The API reports SUCCESS/OCR_APPLIED at91.1% confidence, but output CER is52.83%; exact character/order/numeric checks fail. The source scan pixels are retained, but overlay/masking and native-text checks alone do not establish readable edited output. It is unsafe to treat the uncomposited image as additional visible content after masking/editing. This is the highest measured next priority: distinguish visible composited content from covered original scan pixels while preserving genuinely uncovered text, original coordinates, numbers and deadlines. This batch does not manufacture a threshold or deduplication workaround.

Neither issue is claimed newly introduced by iteration24; they are newly reproduced composition failures in the current source. A future fix must use the frozen failed inputs and independent mixed-content controls, not merely lower the coverage requirement or drop conflicting numbers.
