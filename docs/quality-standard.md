# 质量标准

FormatConverter 使用“路线质量等级 + 可复现 QA 证据”描述转换能力。项目不会用一个笼统的“支持”掩盖不同格式之间的复杂度。

## 转换目标

### 保真优先

保真优先关注页面看起来是否接近原件，适合打印、归档和预览。

常见实现：

- 源文档先渲染为 PDF 或图片；
- 目标 DOCX/PDF/PPTX 中包含页面图层；
- 文本结构编辑能力可能有限。

### 可编辑优先

可编辑优先关注文字、段落、表格、图片等对象是否可二次编辑，适合后续修改。

常见实现：

- 解析源格式的结构化对象；
- 在目标格式中重建段落、表格、图片和样式；
- 复杂版式可能发生分页、字体或坐标差异。

## QA 结论字段

- `strictPass`：按路线目标执行严格检查。直接保真路线要求渲染像素一致；可编辑文档要求规范化内容一致；PDF -> DOCX 还要求纯文字多页样本页数一致、输出含真实文本节点且不含图片，含中日韩文字时必须包含字体表和 OOXML 混淆字体部件，并要求纯图片样本严格失败为 `OCR_REQUIRED`；OFD -> TXT 要求多栏顺序、表格行列正确，纯扫描和混合扫描页严格失败为 `OCR_REQUIRED`；表格路线要求数据一致；JPEG 使用声明的有损误差上限。
- PDF -> OFD 的 experimental 门禁要求输出是含 `OFD.xml` 的真实包、页数和页面尺寸一致、文字型样本字符守恒且每页包含保真图像对象；视觉回环差异单独记录，不能把图像层称为独立矢量对象重建。
- OFD -> XLSX 的 experimental 门禁要求高置信度识别表格的单元格文字、工作表分页和矩形合并区域一致；低置信度或无可靠表格必须返回 `NO_TABLE_FOUND`，扫描页必须返回 `OCR_REQUIRED`，不能返回空工作簿或可疑数据。
- OFD -> PNG/JPEG 的 beta 门禁要求输出页数、顺序、160 DPI 对应像素尺寸和非空页面内容正确；单页必须返回目标图片，多页必须返回编号连续的 ZIP，扫描图像页不得错误要求 OCR。JPEG 另使用有损误差边界。
- PDF -> TXT 的 beta 门禁要求文字内容、左右分栏阅读顺序和换页边界正确；纯扫描样本及含无文字扫描页的混合样本必须返回 `OCR_REQUIRED`，真正空白页允许输出空页面，不能把扫描页静默当作空白页。
- DOCX -> TXT 的 beta 门禁要求正文段落与表格保持 XML 对象顺序，并验证页眉页脚、文本框、脚注尾注、批注作者以及插入/删除修订文字均以明确标签导出；输出大小按 UTF-8 字节严格受限。
- TXT -> DOCX/PDF 的 stable 门禁要求 UTF-8 BOM、UTF-16 BOM 和 GB18030 中文内容守恒，换页符生成真实分页，PDF 自动分页受页面上限约束；DOCX 包含可编辑文字及明确的东亚字体声明，未显式配置东亚字体时对中日韩文字按需嵌入内置许可字体；二进制控制内容必须严格失败。
- CSV <-> XLSX 的 stable 门禁要求常见编码与分隔符识别、引号/换行字段解析、公式注入字符串不被写成公式、日期格式化值和公式缓存结果明确导出、多工作表按顺序完整打包，以及超过内存窗口的行集可由流式 XLSX 写入器完成；畸形引号和资源上限必须严格失败。
- PNG/JPEG -> PDF 的 stable 门禁要求内嵌 DPI 转换为正确物理页尺寸、EXIF 方向 1-8 的矩阵应用、透明 PNG 的可见合成、缺失/异常 DPI 的明确警告，以及同格式多图按上传顺序合并且页数一致；网页端源图预览必须同步重排顺序，真实结果预览的页数与成功页面一致。超大像素和超出 PDF 安全页尺寸的输入必须失败。
- HTTP QA 对 PNG/JPEG -> PDF 以源像素、可信 DPI 和 EXIF 方向推导 PDF 物理页尺寸，不把 LibreOffice 的 A4 图片排版当作格式标准。透明栅格比较必须先合成到白底；PDFBox 与 Poppler 的跨引擎抗锯齿允许 `0.001` 的差异像素比例，但页数、尺寸、元数据和透明语义仍需精确通过各自门禁。
- PDF -> PNG/JPEG 的 stable 门禁要求配置 DPI 对应的像素尺寸与文件元数据一致、PNG 透明画布不被白色填平、CMYK 内容可输出为 RGB JPEG、多页 ZIP 顺序连续；CropBox/UserUnit 导致的超大位图必须在分配内存前失败，加密文件必须返回稳定错误码。
- PDF 压缩的 beta 门禁要求输出可重新打开且页数一致、结果不大于源文件；无损模式不改变源文件视觉，均衡/强力模式必须在图片型样本上证明体积下降并保持页面可用。转换前只能标为源文件预览，完成后必须渲染真实结果；模式变化后旧结果必须降级为“上次结果”并要求重新生成。已优化文件需保留原文件并返回 `PDF_SIZE_NOT_REDUCED`，加密和签名输入必须返回稳定错误码。
- PDF 合并/拆分的 stable 预览门禁要求文件重排后预览仍绑定正确输入，拆分页码按真实总页数去重、升序并拒绝越界；转换后的 PDF 结果按实际下载 MIME/文件名判断后预览，ZIP 不自动解包。预览必须说明重写后不保留数字签名有效性。
- PDF 水印的 beta 门禁要求页数不变、指定页面含可提取的中英文水印文字、未选页面不出现水印，并覆盖不透明度、角度、视觉页面位置、平铺、页码范围、本地预览、独立 Worker 参数透传、加密和签名输入。
- DOCX/XLSX/PPTX -> PDF 的 beta 门禁要求使用真实 LibreOffice headless 转换、输出可由 PDFBox 重新打开且页数一致，并能提取各源格式的拉丁与 CJK 测试文字。CI 在 Linux 安装 LibreOffice 和 Noto CJK 字体执行独立集成回归；生产部署应额外锁定引擎版本和字体镜像。
- 外部进程门禁要求输出始终被主动排空但只保留有限字节，持久化日志与异常消息不得出现本地绝对路径；通用转换器、Worker 响应、任务 manifest 和 API 错误也必须统一清理 Unix/Windows 绝对路径、控制字符并限制长度。超时及线程中断必须终止父进程和已派生子进程，并由自动化测试验证子 PID 不再存活。
- OCR 路线必须按需调用、校验引擎和全部语言包，且输出带 `OCR_APPLIED`、0-1 页级平均置信度和必要的 `OCR_LOW_CONFIDENCE` 警告。官方发布包内置 OCR 时允许自动启用能力，但不能把 OCR 变成原生文字页或固定版式渲染的默认步骤，并必须允许通过 `FORMAT_CONVERTER_OCR_ENABLED=false` 强制关闭。独立 CI 验证内置运行时发现、动态库/模型自检、中英文、数字、标点、旋转图片、图片到可编辑 DOCX 和命令参数安全；PDF/OFD 混合页仍只补齐扫描页。未启用时扫描提取必须返回 `OCR_REQUIRED`；能力缺失、页面模型缺页、无文字、低于硬阈值、超时或资源终止必须返回对应稳定错误码且不发布不完整输出。
- DOCX -> UOF 的 experimental 门禁要求输出是含 UOF 命名空间和 `uof:UOF` 根元素的真实 XML，并由 LibreOffice 重新打开为 DOCX 验证正文段落与表格单元格文字；仅生成文件或修改扩展名不算通过。WPS/ET/DPS 反向写出在没有真实过滤器和重开证据前保持 planned。
- `visualPass`：源文件和目标文件经当前环境二次渲染后的差异低于参考阈值。它受字体和渲染引擎影响，与内容或内嵌页面是否严格一致分开记录。
- `practicalPass`：视觉用例中等同于 `visualPass`；数据和内容用例中等同于 `strictPass`。
- `diffRatio`：差异像素数除以总像素数。
- `pageCountMatch`：源渲染页数和目标渲染页数一致。

## 质量等级

| 等级 | 要求 | 适用场景 |
| --- | --- | --- |
| stable | 样本集严格通过，或数据回环完全一致；无已知内容丢失问题。 | 推荐普通用户使用。 |
| beta | 主流程可用，但复杂字体、版式或外部引擎可能造成差异。 | 可试用，重要文件需人工复核。 |
| experimental | 能运行，但样本覆盖不足、存在明显取舍或依赖不稳定外部能力。 | 面向贡献者和早期验证。 |
| planned | 已规划但未开放执行。 | 仅展示路线方向。 |

## 发布门禁

合并转换路线前至少满足：

1. 不让服务进程崩溃。
2. 不静默少页或少文件。
3. 失败时返回可理解错误。
4. 端到端 QA 有样本覆盖。
5. README 能力矩阵中标注真实质量等级。

标记为 `stable` 前还需要：

1. 样本集严格通过，或给出明确的数据等价证明。
2. 覆盖多页、中文字体、表格、图片和异常输入。
3. 在至少一个干净环境中重新构建和验证。
