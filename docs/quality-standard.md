# 质量标准

FormatConverter 使用“路线质量等级 + 可复现 QA 证据”描述转换能力。项目不会用一个笼统的“支持”掩盖不同格式之间的复杂度。

## 转换目标

### 保真优先

保真优先关注页面看起来是否接近原件，适合打印、归档和预览。

常见实现：

- 源文档先渲染为 PDF 或图片；
- 目标 DOCX/PDF/PPTX 中包含页面图层；
- 文本结构编辑能力可能有限。

### 可编辑优先

可编辑优先关注文字、段落、表格、图片等对象是否可二次编辑，适合后续修改。

常见实现：

- 解析源格式的结构化对象；
- 在目标格式中重建段落、表格、图片和样式；
- 复杂版式可能发生分页、字体或坐标差异。

## QA 结论字段

- `strictPass`：按路线目标执行严格检查。直接保真路线要求渲染像素一致；页面图层 DOCX 要求内嵌页面像素一致；可编辑文档要求规范化内容一致；表格路线要求数据一致；JPEG 使用声明的有损误差上限。
- `visualPass`：源文件和目标文件经当前环境二次渲染后的差异低于参考阈值。它受字体和渲染引擎影响，与内容或内嵌页面是否严格一致分开记录。
- `practicalPass`：视觉用例中等同于 `visualPass`；数据和内容用例中等同于 `strictPass`。
- `diffRatio`：差异像素数除以总像素数。
- `pageCountMatch`：源渲染页数和目标渲染页数一致。

## 质量等级

| 等级 | 要求 | 适用场景 |
| --- | --- | --- |
| stable | 样本集严格通过，或数据回环完全一致；无已知内容丢失问题。 | 推荐普通用户使用。 |
| beta | 主流程可用，但复杂字体、版式或外部引擎可能造成差异。 | 可试用，重要文件需人工复核。 |
| experimental | 能运行，但样本覆盖不足、存在明显取舍或依赖不稳定外部能力。 | 面向贡献者和早期验证。 |
| planned | 已规划但未开放执行。 | 仅展示路线方向。 |

## 当前本地 QA 基线

最近一次本地端到端 QA：

```text
Total: 13
Strict passed: 13
Strict failed: 0
Visual threshold passed: 6
Office available: true
```

路线级严格检查全部通过：

- `DOCX -> PDF`
- `XLSX -> PDF`
- `PPTX -> PDF`
- `WPS -> DOCX`：规范化文本一致。
- `ET -> XLSX`：首个工作表 CSV 数据一致。
- `DPS -> PPTX`
- `UOF -> DOCX`：内嵌页面图像像素一致。
- `PDF -> PNG`
- `PDF -> JPEG`：平均绝对误差在声明阈值内。
- `PDF -> DOCX`：内嵌页面图像像素一致。
- `PNG -> PDF`
- `CSV -> XLSX -> CSV`
- `OFD -> DOCX`：忽略空白后，源 OFD 与 DOCX 的文字字符及数量一致（561/561）。

跨引擎二次渲染仍有差异的路线：

- `WPS -> DOCX`：页数一致，存在小比例视觉差异。
- `ET -> XLSX`：页数一致，存在小比例视觉差异。
- `UOF -> DOCX`、`PDF -> DOCX`：内嵌页面与源渲染完全一致，但 DOCX 经 LibreOffice 再渲染时存在抗锯齿或页面定位差异。
- `PDF -> JPEG`：有损编码导致大范围微小像素变化，平均绝对误差仍在阈值内。

这些视觉差异不会被写成“完全一致”。本轮 13/13 表示每条路线声明的严格目标全部满足，不表示所有目标文件经任意办公软件再次渲染都能达到零像素差异。

完整报告由 `python3 qa-samples/run_qa.py` 生成到 `qa-samples/report/qa-report.md`。

## 发布门禁

合并转换路线前至少满足：

1. 不让服务进程崩溃。
2. 不静默少页或少文件。
3. 失败时返回可理解错误。
4. 端到端 QA 有样本覆盖。
5. README 能力矩阵中标注真实质量等级。

标记为 `stable` 前还需要：

1. 样本集严格通过，或给出明确的数据等价证明。
2. 覆盖多页、中文字体、表格、图片和异常输入。
3. 在至少一个干净环境中重新构建和验证。
