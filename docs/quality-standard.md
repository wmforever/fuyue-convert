# 质量标准

FormatConverter 使用“路线质量等级 + 可复现 QA 证据”描述转换能力。项目不会用一个笼统的“支持”掩盖不同格式之间的复杂度。

## 转换目标

### 保真优先

保真优先关注页面看起来是否接近原件，适合打印、归档和预览。

常见实现：

- 源文档先渲染为 PDF 或图片；
- 目标 DOCX/PDF/PPTX 中包含页面图层；
- 文本结构编辑能力可能有限。

### 可编辑优先

可编辑优先关注文字、段落、表格、图片等对象是否可二次编辑，适合后续修改。

常见实现：

- 解析源格式的结构化对象；
- 在目标格式中重建段落、表格、图片和样式；
- 复杂版式可能发生分页、字体或坐标差异。

## QA 结论字段

- `strictPass`：按路线目标执行严格检查。直接保真路线要求渲染像素一致；可编辑文档要求规范化内容一致；PDF -> DOCX 还要求纯文字多页样本页数一致、输出含真实文本节点且不含图片，并要求纯图片样本严格失败为 `OCR_REQUIRED`；OFD -> TXT 要求多栏顺序、表格行列正确，纯扫描和混合扫描页严格失败为 `OCR_REQUIRED`；表格路线要求数据一致；JPEG 使用声明的有损误差上限。
- PDF -> OFD 的 experimental 门禁要求输出是含 `OFD.xml` 的真实包、页数和页面尺寸一致、文字型样本字符守恒且每页包含保真图像对象；视觉回环差异单独记录，不能把图像层称为独立矢量对象重建。
- OFD -> XLSX 的 experimental 门禁要求高置信度识别表格的单元格文字、工作表分页和矩形合并区域一致；低置信度或无可靠表格必须返回 `NO_TABLE_FOUND`，扫描页必须返回 `OCR_REQUIRED`，不能返回空工作簿或可疑数据。
- OFD -> PNG/JPEG 的 beta 门禁要求输出页数、顺序、160 DPI 对应像素尺寸和非空页面内容正确；单页必须返回目标图片，多页必须返回编号连续的 ZIP，扫描图像页不得错误要求 OCR。JPEG 另使用有损误差边界。
- PDF -> TXT 的 beta 门禁要求文字内容、左右分栏阅读顺序和换页边界正确；纯扫描样本及含无文字扫描页的混合样本必须返回 `OCR_REQUIRED`，真正空白页允许输出空页面，不能把扫描页静默当作空白页。
- DOCX -> TXT 的 beta 门禁要求正文段落与表格保持 XML 对象顺序，并验证页眉页脚、文本框、脚注尾注、批注作者以及插入/删除修订文字均以明确标签导出；输出大小按 UTF-8 字节严格受限。
- TXT -> DOCX/PDF 的 stable 门禁要求 UTF-8 BOM、UTF-16 BOM 和 GB18030 中文内容守恒，换页符生成真实分页，PDF 自动分页受页面上限约束，DOCX 包含可编辑文字及明确的东亚字体声明；二进制控制内容必须严格失败。
- `visualPass`：源文件和目标文件经当前环境二次渲染后的差异低于参考阈值。它受字体和渲染引擎影响，与内容或内嵌页面是否严格一致分开记录。
- `practicalPass`：视觉用例中等同于 `visualPass`；数据和内容用例中等同于 `strictPass`。
- `diffRatio`：差异像素数除以总像素数。
- `pageCountMatch`：源渲染页数和目标渲染页数一致。

## 质量等级

| 等级 | 要求 | 适用场景 |
| --- | --- | --- |
| stable | 样本集严格通过，或数据回环完全一致；无已知内容丢失问题。 | 推荐普通用户使用。 |
| beta | 主流程可用，但复杂字体、版式或外部引擎可能造成差异。 | 可试用，重要文件需人工复核。 |
| experimental | 能运行，但样本覆盖不足、存在明显取舍或依赖不稳定外部能力。 | 面向贡献者和早期验证。 |
| planned | 已规划但未开放执行。 | 仅展示路线方向。 |

- `PNG -> PDF`
- `CSV -> XLSX -> CSV`
- `OFD -> DOCX`：忽略空白后，源 OFD 与 DOCX 的文字字符及数量一致（561/561）。

跨引擎二次渲染仍有差异的路线：

- `WPS -> DOCX`：页数一致，存在小比例视觉差异。
- `ET -> XLSX`：页数一致，存在小比例视觉差异。

这些视觉差异不会被写成“完全一致”。历史 13/13 不表示当前 PDF -> DOCX 实现已完成新的端到端样本门禁；当前路线以可编辑内容守恒、页数一致和纯文字样本零图片为严格标准，二次渲染视觉差异仅作为参考。

完整报告由 `python3 qa-samples/run_qa.py` 生成到 `qa-samples/report/qa-report.md`。

## 发布门禁

合并转换路线前至少满足：

1. 不让服务进程崩溃。
2. 不静默少页或少文件。
3. 失败时返回可理解错误。
4. 端到端 QA 有样本覆盖。
5. README 能力矩阵中标注真实质量等级。

标记为 `stable` 前还需要：

1. 样本集严格通过，或给出明确的数据等价证明。
2. 覆盖多页、中文字体、表格、图片和异常输入。
3. 在至少一个干净环境中重新构建和验证。
