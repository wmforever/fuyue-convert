# 混合 PDF 普通提取/无新增 OCR 路由诊断

基线 `4022840f961d2fe0d0d39c46593a3e238dd5ecd5`；沿用 wmforever 同一分支/草稿 PR #1。iteration33 的局部 Word 金额可见性已有限验收，八项 API `OCR_NO_NEW_TEXT` 和一项 `OCR_VISIBILITY_UNCERTAIN` 未验收。本批复用全部失败 PDF/HTTP 证据，不重跑 Word 可视矩阵、不重新识别原稀疏 OFD。

## 路由与实际 gate

`DefaultConverterRegistry` 注册一条 PDF→TXT 提取路线，并按全局配置传入 OCR 引擎。不存在另一个“必须产生新增文字”的显式 PDF OCR-augmentation route，也不存在请求级“忽略扫描只返回现有文字”的安全模式。`PdfToTextConverter` 调用 `recognizeMissingPagesForText`；其 `respectVisibility=true` 与 Word 路线的 false 区别是可见性分析，不是提取/新增意图。

纯原生页的必需扫描列表为空时直接保留原生文字，不要求新 OCR。混合页先由共享 `ScannedContentDetector` 判断是否有扫描缺少足够原生层：至少 80 个非空白字符、占 4 个垂直带中的 3 个、跨度至少图高 45%。保存的九份 PDF 原生文字只有 **51–55 字符、2 个带、跨度 27.3%/31.5%**，全部触发一个必需扫描区域。它们的原生文字已经有新金额，但这个事实不能证明其余扫描内容没有遗漏。

必需区域 OCR 先要求可用结果，再按已证明不透明遮罩过滤源词，最后去重原生文字。若剩余全部是原生重复，当前严格 `OCR_NO_NEW_TEXT`。若所有识别词都已遮挡且确有隐藏词，则已有零新增成功条件。新控制中整张扫描图确实被不透明矩形覆盖时，这个 no-op 合法；仅凭“所有 OCR 词被覆盖”仍不是一般全文完整性的证明，未将其推广到含未知未识别内容的页面。

因此没有证明这里错误调用了“显式新增 OCR 路线”。已知完全正确的独立合成稀疏页面也被保守拒绝，说明误拒绝真实存在；当前模型缺少足以安全区分“完整重复”与“仍有未识别内容”的证明。

## 冻结独立控制与真实 HTTP

先冻结七份新 PDF/源 PNG、两层真值、遮罩和字体，再使用**未修改的当前 JAR**运行一次上传→独立 JVM→下载/严格无下载。没有重复原来的九次 API 或 Word/Office 矩阵。

| 控制 | 实际结果 | 证明范围 |
| --- | --- | --- |
| 纯原生四行，无图像 | 成功；全文/数字精确，无 OCR 警告 | 普通提取不要求新 OCR |
| 完整原生四行＋局部旧金额遮罩 | `OCR_NO_NEW_TEXT`，无下载 | 完整合成页保守误拒绝仍存在 |
| 完整原生四行＋覆盖整图的不透明矩形 | 成功；全文/数字精确，隐藏源词警告 | 真正整图不可见时可无新增返回 |
| 原生层缺日期＋局部金额遮罩 | 成功；补入真实扫描日期，全文精确 | 返回已有原生文字会遗漏真实内容 |
| 局部遮罩＋额外 14px 小字 | `OCR_NO_NEW_TEXT`，无下载 | 仅重复识别结果不能证明完整 |
| 原生 `00973` / 扫描 `00974` | 成功；两值保留 | 不选择一个“可信”金额；平铺结果非单一真值 |
| 半透明金额遮罩 | `OCR_VISIBILITY_UNCERTAIN`，无下载 | 不放宽不确定可见性 |

小字控制确实含 **`MISSING 0063.10`**，在原生文字块和金额遮罩之外。300 DPI 实际 PDF 裁剪与源图对应区域逐像素完全一致，未被隐藏，含显著黑色字迹；只提取现有原生块没有该文字。它与完整重复控制同样返回 `OCR_NO_NEW_TEXT`。把“剩余 OCR 都是原生重复”直接改成成功，会把这个真实可见内容静默遗漏。这是实际产物反例，不以高置信度或猜测“应该没有其他字”放行。

`PdfRouteNativeProbe34` 只解析 16 份文件（九份原失败＋七份新控制），重新计算检测器输入和现有原生提取结果，**OCR 0 次、Office 0 次**。原九份 API 失败复用缓存报告，生产 OCR scratch 没有保存可复用 TSV；没有冒称已有完整识别模型。本批实际新 HTTP 7 次、4 成功/3 严格失败，全部 worker 身份消失、ECHILD、0 新增僵尸。完整原生和部分原生成功输出均精确为 `Amount 128.75`，没有旧 `127.50`；数字、前导零、日期和分隔保留。

## 结论、来源与停止边界

**未证明可安全修正的生产路由/gate 错误，生产实现不变。** 没有凭原生文字非空、扫描 OCR 无新增、平均置信度、少量 bounding box 或自产标记允许空成功。完整可见扫描内容已有原生层的证明尚未建立；任意未知字迹可位于识别框之外，框内空隙也不能自动当作原生文字覆盖。原 OFD novelty、数字去重、透明/部分遮挡、原图/Word 坐标和时限契约保持原样。

JAR 仍是 `6e0f7d94a2e0804074cc535c04a859e7f6c5fd8171cf94a21f9ba4b4a2434c6c`，构建输入仍 `da4cdd3ad198252de69fb197ad4820ee1094d13ae5e139f22f3eae5c25e9670d`。iteration33 的 22 个已下载产物哈希重新核对，Word/PDF 没有变化。沿用该精确生产源码已通过的 496 项构建测试（495 通过、1 可选签章夹具跳过）和 pinned bundled OCR 验收，不重跑未变化的构建。这里的 Maven 数不是本批重复执行数。

新真实 HTTP 使用同一固定 Tesseract 5.5.2/Leptonica1.87.0 和模型清单，源码及模型/字体精确版本见 [iteration33 验证](cloud-mixed-masks33-validation.json)。独立合成源字体 Liberation Sans 2.1.5、14/56px；PDF 生成/实际渲染 PyMuPDF 1.26.6。原生 macOS/Windows 安装器、Microsoft Word 和可选签章夹具仍未运行。运行时墙时/CPU/峰值子进程 RSS、源/产物/几何/生成器哈希和警告见 [完整诊断](cloud-route34-results.json)，不把不同工作量宣称性能改进。
