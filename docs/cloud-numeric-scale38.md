# 有界数字缩放对照：候选不采用

父任务固定当前生产起点 `822442bb0df0fa1adda5c246b840ed9d6ab0c9d6`，只调查混合 PDF 内嵌图像的 1600px 缩放是否损害数字。仓库、分支和草稿 PR #1 延续既有任务，`main` 仍为 `e3ffde164e90e766b7a9d6e3b1fae3f53b94d7d5`。本轮新增可复现 QA 和证据，**未修改生产代码、JAR、分辨率限制、重试或质量门禁**。

## 冻结输入与实际结果

生成器在任何本轮 OCR 之前冻结六个独立中英文文字扫描：两种语言各 56/38/24px 字号，另有空白和固定种子的 24 个孤立灰点控制。所有源图 2000×1700，字体分别用 Liberation Sans 绘制 ASCII、Droid Sans Fallback 绘制中文；不使用缺 Latin 字形的 CJK 字体绘制数字。每页包含合成编号 `00946`、日期 `2089-07-23`、金额 `+073.26`、余额 `-0058.40`、分开的 `12 34` 和 `15.25%`。PDF 有图像区域以外的单带原生页眉，实际走内嵌图像 OCR；没有编辑/遮罩干扰。源图/PDF、真值、版本、字体和生成器均 SHA 绑定。

只移除空白计算内容 CER，保留大小写、数字、符号和标点；另外比较逐个数字字符串的有序序列，包括符号、前导零、日期和 `12 34` 边界。字符/数字指标与实际文字一同保存，不能由平均置信度推断完整性。

| 路径 | 字符错误/492 | 内容 CER | 完全文字正确 | 数字序列正确 |
| --- | --- | --- | --- | --- |
| 当前 1600px bicubic | 1 | 0.2033% | 5/6 | 5/6 |

当前中文 24px 将 `+073.26` 识别成 **`f073.26`**。数字序列提取器看到 `073.26`，因此“符号丢失”指标不能代替完整实际文字。当前平均置信度 **92.1721%**，错误词置信度 **56.8563%**，`possibleTextOmission=false`。实际 API 仍为成功并带 `OCR_APPLIED` 人工复核提示；不声称成功状态或覆盖探针已经证明真值完整。

保留 2000px 修复该小字金额的加号，却在中文 38px 引入 `f073.26` 和 `Se`/`对` 两个额外词；中文 24px 又丢失 `分开`、引入 `y`/`局`。两种空白/噪声控制的三个诊断路径都没有发明文字。**拒绝普遍保留 2000px：错误增多且不同样本的数字退步，不能凭单个 `2097` 观察提高分辨率。拒绝 bilinear：未测得准确率收益。** 不用真值、字号标签或平均置信度在生产选择候选，不改识别出来的数字。

## 原始 PNG 与真实生产前缀

首先执行原始 PNG 对照，32 次诊断 OCR 中有 24 次属于该对照。原始 300DPI PNG 的 2000px 结果为 4/492 错误；实际 PDF 解码图像的 2000px 结果为 8/492。二者 RGB 像素完全一致，PNG 元数据/DPI 不同。这个差异与元数据敏感性一致，但**没有隔离元数据变量做因果试验**，不能声称已定位其唯一原因。

从同一批真实 HTTP 捕获完整 TSV，**六个当前路径 TSV 与已完成 1600px PNG 对照字节完全一致**；不重跑 HTTP。八个实际 PDF 解码后的 bilinear 临时 PNG，与已完成候选输入 PNG **字节完全一致**，因此复用候选结果；该检查只生成临时图像，没有增加 OCR。最初英文模型序列化失败留下的完整 TSV，通过生产解析器和几何细化零 OCR 重建；不重做已完成识别。PDF 解码源 2000px 的八次识别是实际前缀改变后的必要对照，并非重复旧矩阵。

## HTTP、原图、坐标和 Word 边界

新冻结矩阵实际执行 **14 次携认证本地 HTTP→独立 JVM Worker→产物下载，14 次成功**：六组 TXT/DOCX 加两组空白/噪声 TXT。六个 TXT 中五个真值完全正确，中文 24px 的错误金额真实复现。空白/噪声 PDF 只返回一次正确原生页眉，**没有调用 OCR**。六个 Word 内嵌扫描与源图 RGB 像素完全一致，可编辑扫描文字等于实际识别层，原生页眉恰好保留一次。

三个路径的 **348 个识别词框**均落在原图物理坐标中，图像盒为 `[0,8.466666…,169.333333…,143.933333…]` mm；缩放输入不改变原图/布局权威。中文错误金额 Word 保留 `f073.26` 可编辑词，低置信度遮罩仍为负 z-index `-251658751`，没有按高置信度规则提升到前景。仅验证 OOXML 的既有回退配置和原图像素，**未在本轮用 Office 验证它的最终视觉结果**。Word XML 将原生页眉置于扫描词之后；XML 顺序不等于视觉阅读顺序，分别验证两层守恒而不把它宣称为正确流式阅读顺序。

所有 14 个 Worker 和命令登记进程已消失，监督者得到 ECHILD，0 新僵尸。实际 HTTP 64.146s，user/system CPU 163.260/13.770s，最大单子进程 RSS 365324KiB；没有同时峰值内存求和。32 次独立诊断识别、12 次实际 HTTP OCR、0 次重播/输入一致性检查 OCR、0 次新 Office 调用分别计数。两个前置工具错误保留：镜像没有 `/usr/bin/time` 时 0 OCR；Duration JSON 序列化失败发生在一次已完成 OCR 之后，复用其 TSV。两个验证器错误分别因把 Word XML 层次顺序等同阅读顺序、把负层遮罩等同前景遮罩，修正为明确的实际合同断言；没有重跑任何 OCR/HTTP，也未放宽生产断言。

## 重现与停止条件

从干净匹配源码构建 JAR并准备固定内置引擎后，执行生成器冻结一次，提取 JAR 的 `BOOT-INF/classes` 和 `BOOT-INF/lib`，将 `OcrScaleProbe38.java` 编译到 QA classpath。`measure_numeric_scale38.py --out <新目录> --classpath <QA+JAR类路径>` 默认使用真实 PDF 解码源；`--png-source` 显式标记原始 PNG 诊断，`--original-only`/`--bilinear-only` 限定候选。`capture_numeric_http35.py` 配合冻结 `expected.json` 执行新的有限 HTTP 图；其 TSV 抓取不添加引擎调用。验证器检查当前保留证据、路径一致性、真值/数字边界、原图和保守停止决策。

本轮在两个候选无准确率收益且存在实际数字退步时停止生产改动；不继续扩大分辨率、模型或试验次数。保存已验证脚本/样本/结果到同一草稿 PR，由既有父任务/dot 决定下一项不同的有限试验。仍未解决中文小字误识别、元数据差异、原始 sparse OFD、先前混合 Word API 的严格可见性/完整性失败、邻接长金额和 per-mille。新六个 Word 的 Office 视觉/编辑重开、Microsoft Word、原生 macOS/Windows 安装包和 signed fixture 均未运行；云端 JAR/系统 CI 不能代替这些验收。不合并、不发布、不访问 Mac、不重试 Library、不上传外部业务文件、不另开并行写入任务。
