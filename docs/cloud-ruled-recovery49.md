# 扫描表格字段恢复与编辑后逐行回读（iteration49）

本轮实际修复同一条扫描 PDF → 可编辑 Word → 修改金额 → Office PDF → API TXT 链路。起点 `dba208c52659ff1d941f91f7528a47cf629d9ddd`，仓库仅 `wmforever/fuyue-convert`，沿用草稿 PR #1。两份样本均从 **4/9 数据字段变为 9/9**；巨大跨框 `Ce/ee` 等错误候选不再覆盖表头，其原识别文本保存在复核警告中。编辑后的新金额只出现一次，旧金额没有回读，编号、日期、金额按同一行输出。仍有表头 `ID→1D` 和中文表头字距问题，不能称作逐字无误或完整逻辑 Word 表格。

[机器可读结果](cloud-ruled-recovery49-results.json) 保留实际文本、CER、源图/产物哈希、坐标、编辑差异、负控制及成本。精确提交 SHA 和 CI 最终状态记录在同一 PR；本说明不提前宣布远端 CI 成功。

## 根因与采用范围

48 的实际编辑 PDF 中，两个不透明金额遮罩经过 334 个 PDF 操作符验证：没有不透明度、混合模式或原图坐标歧义。`+0085.40` 的旧图像词被完全覆盖，同一 OCR 行中的 `03872` 和日期仍可见，因此现有整行可见性门禁正确返回 `OCR_VISIBILITY_UNCERTAIN`。直接 OCR 最终整页可见像素仍漏掉表格，已拒绝该方案，没有放宽门禁。

更早的源扫描在整页 PSM3 中把真实网格线识别为巨大低置信 `Ce/ee`，并漏掉表头、编号和第一行字段。本轮只对**完整、连续、薄直线、浅色纸面的矩形网格**增加独立区域识别：

- 必须先有低置信、无数字且跨越格线的异常整页词；普通扫描、无线多栏和正常已识别页面不触发区域 OCR。
- 检测最多 500ms、25M 像素、64 格，拒绝断线、粗条、合并格、深色/彩色纸面及模糊边界。每次只裁出一个真实格线内部区域，原图不重采样、不擦线、不覆盖。
- 区域使用 PSM6 单块识别；全页仍为原 PSM3，模型、并发、最低置信度和页级 120s 总时限不变。所有区域调用共享原页剩余时间。失败回退原结果，超时保留 `OCR_TIMEOUT`。
- 每格非空且新词置信度至少 0.75，并保留五个百分点增益门槛；这些门槛不是内容完整性证明。已有数字所在格的**完整词序列**必须逐字一致，包含符号、前导零、货币、括号和单位，禁止新增邻接字符延长数字。
- 原非异常词必须在同格找到文本及位置相符的对应词，随后直接保留原 `OcrWord` 对象。原数字不会用“更高置信”的新值替换。异常跨框原词另存复核警告，源扫描仍完整保留。

恢复出的完整文字层使新 Office PDF 不再需要重读底图旧金额。首次验收另发现 TXT 把字段按栏输出；本轮复用同一框线检测修复该行序。TXT 仅在一个正向、无旋转/透明歧义的扫描图、真实格线未被后绘遮罩覆盖、每格都有完整原生文字、所有文字均可唯一归格时按行输出 TAB 分隔字段。空格、跨格、多行歧义、无间隔数字片段或 OCR 混合词均保留原策略。没有新增 OCR 调用，也没有修改 `PdfOcrVisibility.filter` 的部分遮挡/数字边界规则。

```bash
  --corpus qa-samples/generated/ruled-recovery49 --out qa-samples/work/iteration49-http --keep-going
python3 qa-samples/freeze_ruled_native49.py
python3 qa-samples/capture_numeric_http35.py --jar web-api/target/web-api-0.1.5.jar \
  --corpus qa-samples/generated/ruled-native49 --out qa-samples/work/iteration49-order-http --keep-going

```

`ReplayRuledGeometry49.java` 读取实际 PDF 物理尺寸、原扫描以及全页/区域 TSV，使用当前解析器和选择器，不启动 OCR；记录中保留所有原数值坐标。监督入口仍为 `iteration20-command.py`/`qa_process_guard.py`。审计初次把派生 Word 框顶边误当成 OCR 源坐标而失败，随后改为实际 TSV 选择器对象精确校验，并如实记录派生框差异，没有降低数字、像素或坐标验收标准。
