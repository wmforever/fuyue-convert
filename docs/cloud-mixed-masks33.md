# 混合原生文字/扫描图 Word 遮罩有限验收

父基线：`4c6217978aa264b4ddbcba7c99e502c8a606ff07`。仓库仅 `wmforever/fuyue-convert`，沿用 `improve/cloud-ocr-completeness-20261003` 和草稿 PR #1。本批只修改 `FixedLayoutDocxRenderer` 的局部遮罩层次；OCR 引擎、去重、完整性/时限、原始坐标、数字编辑预留策略均不改。

## 实际问题与有限修正

父版本的混合页已有正确位置和纸色的逐词遮罩，但 `scanOnly=false` 把它们置于 `z-index:-251658751`。Office 实际先画这些负层次形状，再画 DrawingML 扫描底图，最后画 OCR 文本，导致旧扫描金额与编辑值叠印。iteration32 已证明父/当时最终 Word 内容及 Office 像素相同，两项实际质量失败保留为基线。

新行为仅在以下全部条件满足时把该词已有遮罩改到 `z-index:1`：单张 OCR 底图、无矢量/表格/流式段落、有限文字数、原生文字变换为单位矩阵且基线/偏移位于声明边界内，OCR 词框完整位于底图、单位变换、置信度至少 0.85、可靠采样的浅色中性纸面。保护范围包含原生块和包含原生文字的段落，向外扩两倍字体高度；包括没有出现在固定文本列表中的原生正文。任何碰撞保留旧层次。最多 512 个 OCR 词和 512 个保护区域，复杂/密集组合跳过此可选策略。

实际样本的遮罩层次为 1、OCR 文本框为 2，Office 绘制日志证明顺序为扫描图→局部纸色遮罩→OCR 字。源扫描像素、所有原生/OCR 文本、词框、字体、透明文本框及未识别词间区域保留。Word ZIP 除核心时间元数据外，仅这些遮罩的 z-index 变化。纯扫描页、深色纸面全页旧策略、低置信度回退和原扫描页数字编辑预留保持不变。

这不是 OCR 完整性或数值冲突消解。高置信度只参与是否可应用已采样局部遮罩的有限判断，不能证明漏字不存在。

四份金额正常/编辑共八个 Office 结果的遮罩外 300 DPI 像素完全一致；四次编辑的文本框外像素完全一致，唯一编辑值的 Word XML 变更精确验证。比较排除区由实际输出的遮罩/文本框坐标计算，整数像素边缘容差 2 像素，完整区域见 JSON。原扫描像素全部精确保留，注记在遮罩外精确保留。四份编辑金额裁剪使用固定 bundled OCR，原始字符串和数字词元全部精确、局部 raw CER 为 0；不把局部测量推广成全文 CER。

父 API 的正常/编辑输出有多余扫描金额，原始全文 CER：白底 23.44%/23.81%，灰底 22.22%/22.22%，数字边界 18.75%/18.75%，原文件 21.67%/21.67%。最终 API 没有文本产物，CER/完整性不得记成 0 或成功。八项均明确 `OCR_NO_NEW_TEXT`：遮掉旧金额后，剩余图像 OCR 被已存在原生文字去重，严格保护没有获得足以证明完整性的新增文字。保持这个边界，不通过自产标记、置信度或强行删除图像放行。标记样本另外一项严格拒绝部分/不确定可见性。**本批验收 Word 可见性改进，未验收一般 Word→Office→API 全文成功。**

四种数字去重冲突（延长、负号、小数点、单数字差异）原始文本和四项警告精确保留；之前已通过的纯扫描金额编辑及显式数字空白 PDF→TXT 两项仍精确通过。同位置冲突 Word 全部非时间元数据部件精确一致，不选取“更可信”金额。原稀疏 OFD 识别、像素、参数诊断未重跑，严格失败未放宽。

[逐样本证据](cloud-mixed-masks33-results.json)、[构建/版本验证](cloud-mixed-masks33-validation.json) 和当前云端检查点保留准确状态。同分支草稿 PR 将保留精确 SHA、三项 CI 和本地带校验和审阅包。审阅包是 Linux 云端材料，原生 macOS/Windows 安装器、Microsoft Word 和可选签章夹具未验收；现有旧安装器不代表本批代码。
