# Conservative fallback for malformed PDF content tags

Parent `9f50cf63e6d971e1e31fe3c3bc502526ec39cfef`; same branch/draft PR. A finite adversarial follow-up reproduced two optional PDF→TXT grouping defects through authenticated HTTP and the production independent JVM Worker. Reusing one page MCID in separate content sequences, or nesting a normal MCID tag inside `Artifact`, could still authorize section reordering. Visible text and numeric inventory were intact before the fix; the defect was failure to retain the legacy page order when tag metadata was ambiguous.

The parser now records page-local content MCIDs, disables optional section ordering on reuse, and propagates the outermost Artifact depth through nested tags. Artifact membership never discards actual text. Repeated/unsupported input still goes through the unchanged parser and legacy text sorter. The set resets per page and is capped by the smaller of the existing text-object limit and100,000 entries; marked-content stack depth remains64. Existing structure traversal is bounded by64 levels and at most100,000 entries, with identity-cycle detection. A cap disables optional ordering rather than deleting blocks. No Word, OFD, OCR, source text, numeric formatting, coordinates, font mapping or mask code changed.
