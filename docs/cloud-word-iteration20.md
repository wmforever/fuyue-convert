## Rejected narrow-column candidate

A bounded prototype required at least three aligned two-run prose rows, a stable narrow gap, independent native boxes, sentence endings and sufficient letters, with numeric/table/graphics/OCR/transform exclusions. It retained each original immutable TextBlock and allowed only aligned, regularly spaced unequal tails. The prototype's430-test clean build had429 passes/one optional signed-OFD skip. Six new narrow tests passed. Those unit results were insufficient for adoption.

All four narrow DOCX order CERs became0%, from34.1727%,43.4286%,30.0633% and10.2857%. However, actual Office PDF order CERs became58.6331%,60.8571%,55.6962%,28.5714%; API TXT worsened in three cases. Matched source-to-Office box deviation rose from32.726pt to36.976pt in three samples (a partial line-match metric, not complete layout accuracy). All characters/digits remained present, but completeness did not compensate for these regressions.

**The inference and its six tests are removed from final production.** Candidate JAR `a97f9294e324af2276b0572a5e61e56b542ffeceb3950e4bd638430d61e2436a`, source patch, six-test source, native model probe, clean-build reports,29 successful HTTP outputs and before/candidate previews remain in the local review evidence. [Rejected measurements](cloud-word-iteration20-rejected.json) preserve the failures. No rotation, general-flow, threshold or angle sweep was retried. Final narrow behavior and the existing numeric-ledger ambiguity are retained; this is not a general narrow-column solution.

## QA deadline and observation correction

The old480s check ran only at contract entry; fixed30s HTTP calls and downloads outside the120s poll loop could overrun advertised limits. Previous53/67s iteration19 runs remain valid observations, but their old plan did not enforce those hard bounds. Their original evidence, including the final observer exit1, is unchanged.

The shared runner now uses monotonic absolute deadlines: suite480s, HTTP startup36s after supervisor registration, contract120s including upload/poll/download, and each request at most30s or the smaller remaining parent budget. A timer shuts down the connected loopback socket at the deadline, so trickling headers/downloads cannot perpetually reset an idle timeout. CPU/filesystem work checks deadlines at operation boundaries; this is not a kernel-level hard termination guarantee. Supervisor registration has its existing5s allowance within the suite; teardown has a separate15s allowance, plus2s observer join. Unkillable children retain their owning reaper and block further work.

Five Python regressions cover a contract starting at suite second479, shared upload/poll/download budget, real trickling headers/body, and successful responses. They are also added to CI. The unchanged public subreaper supplies teardown; its earlier three teardown gates were not rerun. The observer counts only direct backend JVM Worker identities `(PID,startTicks)`, excluding nested command-line matches. Completed matrices are not rerun solely to repair counts. Final reports include measured runner/deadline/supervisor source hashes.
