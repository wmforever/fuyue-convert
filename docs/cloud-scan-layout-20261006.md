# 扫描混排 Word 的有限修复与质量边界

基线是实际 `v0.1.7` 标签对应的 `03ef20ef5aa6427f08bab025088e1ff15ee7e517`，沿用其 OCR、数字和遮罩保护。隔离分支为 `improve/cloud-scan-layout-20261006`。授权私有原件、失败 Word、截图、TSV 和所有诊断产物仅保存在 Git 忽略目录，没有进入公开仓库；本文只记录不含原文的汇总。

真实 11 页的扫描 PDF 和用户失败 Word 均已实际转换、用本地 Office 重开、导出并逐页渲染。当前生产基线也复现了叠字、宽框覆盖邻词、规则线误识别成巨大词及截图混排问题。本次交付两个有界改善，**整份真实文档仍未通过完整质量验收**。

## 采用的改变

1. 单扫描页中的黑底截图白字，不再使独立采样、可靠、无数字、尺寸受限的浅色正文遮罩退到扫描图后面。原有暗纸白字、数值词法、编辑留白、彩色未知印记和不确定样本政策保留。真实样本只有第3页的51个遮罩因此改善；这项改变不解决第4、5页的主要故障。该页19953个变化像素全部在这些遮罩范围内，其外1131834个像素完全相同。
2. 对数字编号后的完整中文标题，复用既有原图字迹的逐字空白隔断证明来校正词框，编号 `OcrWord` 对象与坐标直接保留。仍要求至少6个中文字符、逐字分离且笔画尺寸/间距符合原有条件。一个低置信前导引号只在几何计数时暂不计作汉字，原引号、全部识别文字和置信度仍保留在可编辑输出中；不据此宣称文字识别正确。短标题、混杂字符、未知字间印记及无法证明的布局回退原结果。

原件重新转换后仍为11页，共2102个可编辑文字框；它们包含既有错误词，不等于2102个正确词。全部既有文字与数字逐词守恒，扫描媒体逐字节相同。第4、5页共13个标题框发生几何/字号调整；其他页面文字框不变。最终13份完整 OCR TSV 与基线逐字节相同，模型、识别文字和置信度未改变，没有新增 OCR 调用，也没有文字 CER 改善的主张。

第4、5页相对基线渲染分别改变2572、3676像素，长标题宽框重叠减轻；低置信词局部仍叠字。真实 Word 中一次等长度中文编辑经过 Office 重开，新文字可见、对应原文字层不再包含旧值；仅第4页的557个像素变化，其余10页完全相同。未使用隐藏文字、整页白色遮罩或删除错误词换取通过。

## 尚未解决

## 合并后的首词边缘复验与修复

PR #8 已按后续授权合并到生产开发分支 `improve/cloud-ocr-completeness-20261003`，合并提交为 `5bff9bff4f7f77d53fd00d41d14ae0e573851c2c`。合并后的源码树与原验收提交一致；绑定同一 JAR 后，经生产 API/独立 Worker 实际 Office 重开，11页渲染与合并前逐像素一致。

进一步核查原图发现，编号中文标题首词的识别框切掉了左侧6像素笔画。旧逐字细化只在原框内部搜索，无法恢复这段笔画，且纸色采样在切断的边缘上拒绝生成遮罩，导致可见重影。新增修复仅对已符合原有完整中文标题规则的场景检查左侧边缘：搜索宽度不超过首词高度的四分之一、最多25000像素；外边界必须有连续三列空白；所有新增深色像素必须与旧边界字迹连通。逐像素检查新增区域的颜色，独立黑点、彩色印记、贴近数字编号、缺失空白隔断均回退。随后仍须通过原有逐字字迹/间距证明和纸色采样。数字对象、原识别文字、置信度、原图和超时政策保持不变。

首轮真实11页 PDF→Word→Office 复验中，只改变第4页首词的一个框，新增一个局部纸色遮罩；原2102个词框的文字/数字以及全部11份扫描媒体字节均相同，其余10页渲染逐像素一致。220 DPI实际 Office 裁图确认该词重影消失。第4页仅711像素变化，全部位于该词的新旧文字框与新增遮罩的并集内；其中12像素属于文字移动后在遮罩上方的笔画变化，不能表述为“所有变化都在遮罩内”。新增彩色保护后的最终构建也完成11页真实PDF→Word→Office复验：所有文字框/遮罩与首轮候选相同，Office渲染逐页逐像素相同。
